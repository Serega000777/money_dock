# ADR 0010: Amola Assistant и Financial Voice Engine

## Статус

Принято, внедряется вертикальными срезами.

## Решение

- Быстрые команды сначала проходят нормализацию и детерминированный parser.
- Локальное распознавание устройства остаётся бесплатным fast path там, где оно стабильно.
- Серверный STT — Yandex SpeechKit через `SpeechToTextProvider`; загруженное аудио не хранится.
- Сложный язык маршрутизирует DeepSeek; GigaChat вызывается только после retryable-сбоя primary.
  Адаптер DeepSeek поддерживает прямой API и OpenAI-совместимый Yandex AI Studio;
  production использует управляемый `deepseek-v4-flash` через настраиваемые base URL,
  auth scheme и model URI.
- LLM выбирает intent или разделяет фразу, но не считает финансовые показатели и не пишет в БД.
- Read tools получают готовые агрегаты существующих сервисов.
- Любой write создаёт `assistant_pending_actions`; payload хранится на сервере и исполняется только по `actionId` после подтверждения.
- `clientId` действия обеспечивает идемпотентность повторного подтверждения.
- OpenAI/Gemini STT остаются legacy-кодом для безопасного rollback, но не входят в новый runtime.

## Безопасность и приватность

Все сущности скоуплены `userId`; чужие идентификаторы дают 404. В LLM не отправляются JWT,
ключи, DB URL или массивы транзакций. В production-логах остаются только provider, latency,
token counters и fallback count — без текста разговора и финансовых payload.

## Последствия

Приложение продолжает работать без LLM-ключей: простые команды и детерминированные вопросы
доступны. Без Yandex-ключа серверный голосовой ввод сообщает о временной недоступности,
но текстовый ввод и локальное распознавание не блокируются.
